## 0. Invariant rules
1. No fake data (volume, KD, rank, traffic, backlinks, CPC, AI visibility, impact). Missing → "not connected" / "insufficient data" / "unknown".
2. Every datum has source class: FIRST_PARTY | OBSERVED (own crawl / SERP snapshot) | PROVIDER | MODELED (with model_version) | AI. Shown in UI/API/exports/opportunities. Never sum across classes (GSC clicks ≠ est. traffic; GSC avg position ≠ tracked rank).
3. Never scrape Google SERP/autocomplete; no CAPTCHA/anti-bot bypass, no proxy rotation. SERP only from licensed providers.
4. Third-party sites: robots.txt, no login/paywall/private areas, global per-host politeness across tenants, bot info page + opt-out.
5. Correlation ≠ causation ("observed"); no ranking guarantees; estimates with uncertainty ranges.
6. Tenant data never leaks into global datasets; cross-tenant use only opt-in, aggregate, k-anonymity.
7. Don't copy competitor product names/metric names/UI/data.
8. Secrets never in code/logs/frontend.
9. Untested ≠ done; never delete/weaken tests; report passed/failed/not-run separately.

Data source strategy: own perf = GSC/GA4 (+Bing/Yandex WMT, server logs); SERP/ads = licensed SERP API (DataForSEO/SerpApi/Bright Data); volume/CPC = Google Ads Keyword Planner or provider; ideas = provider + own SERP snapshots (PAA/related) + tenant GSC queries (tenant-only); ranked keywords = own SERP DB + provider; backlinks = own discovery crawler + Common Crawl bootstrap + provider; domain traffic = MODELED (rank×volume×CTR, calibrated with GSC); clickstream = UNSUPPORTED without license; CWV = CrUX/CrUX History/PSI; AI visibility = official LLM APIs + SERP providers with AI Overview. Unconnected provider → module still runs, shows "not connected" + setup + cost.

## 1. Architecture
- Services/profiles: core (api, worker, postgres, frontend — standalone), analytics (+ClickHouse, MinIO, Redis), crawl (+discovery crawler, Playwright renderer, egress-proxy e.g. Smokescreen), observability (Prometheus/Grafana/OTel), full. Workers: worker-sync, worker-analysis, worker-crawl-audit, scheduler. Ports 127.0.0.1. Crawler/renderer on separate network, no direct DB access (queue/object storage) or ADR.
- Postgres = control plane (org/user/project/site/competitors/settings/jobs/opps/billing/audit log/encrypted creds). ClickHouse = analytics (keyword_metrics, serp_snapshots/serp_results, domain_keyword_rankings MV, rank_tracking_results, backlinks/link_graph, large GSC/GA4 facts, crawl_pages at scale, ai_visibility_results), monthly partitions, TTL, ngram/token bloom index, ReplacingMergeTree+version idempotency, document FINAL/argMax. MinIO = WARC, raw provider responses, HTML snapshots, reports/exports; content-addressed, traversal-safe. ADR for dual-write vs migration of existing PG GSC/GA4/crawl tables + backfill command.
- Jobs: Postgres jobs+schedules tables, SKIP LOCKED, lease+heartbeat, backoff+jitter, dead-letter, idempotency key, priority, per-tenant fairness, checkpoint/resume, scheduler leader via pg_advisory_lock, simple DAG fan-out/fan-in (e.g. N SERP → rank → visibility → alerts), LISTEN/NOTIFY → SSE progress. Temporal only via ADR.
- Semantic metric layer: single registry (name, formula, source class, unit, valid dimensions, aggregation, timezone); UI/API/reports/alerts/assistant query only through it; generate docs/metrics.md; block invalid combos (GSC byPage vs byProperty, summing avg position).
- Global vs tenant data; isolation via Postgres RLS + ClickHouse row policy + mandatory tenant_id (non-bypassable).
- Lineage on every record: source_class, provider, provider_request_id, fetched_at, model_version, cost_units, MinIO raw ref. Freshness policy per type; "last updated" everywhere.

## 2. Multi-tenant SaaS

- Plans/limits/credits: unit costs (SERP req, keyword lookup, backlink query, AI prompt, crawled page, export row); plan limits (projects, tracked keywords, monthly crawl pages, users, monthly credits); preflight cost estimate + confirmation; per-tenant usage & provider cost; admin margin dashboard; global provider budget caps (daily/monthly) stop + alert; Stripe behind flag (test mode locally).

## 4. Normalization
